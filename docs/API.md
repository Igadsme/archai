# API

`GET /health` and `GET /readiness` report service/configuration status. `GET /v1/infrastructure/workers` and `/v1/infrastructure/queue` expose operational state. `POST /v1/architectures/validate` accepts a strict Architecture JSON document and returns its canonical hash plus analytical metrics. `POST /v1/architectures`, `GET /v1/architectures`, `GET /v1/architectures/{architecture_id}`, and `GET /v1/architectures/compare` provide the local registry surface. `GET /v1/models` and `GET /v1/models/{model_id}` expose registered checkpoint metadata. `POST /v1/architectures/generate` loads a configured generator checkpoint from `ARCHAI_GENERATOR_CHECKPOINT` and returns independently seeded, canonicalized candidates; it returns `503` when no checkpoint is configured. `POST /v1/searches` creates a budgeted search job and accepts optional benchmark indices; `GET /v1/searches/{search_id}` reports the authoritative job-store status and `POST /v1/searches/{search_id}/cancel` transitions queued/running jobs to cancelled. Starting a search returns `503` without Redis, and the durable worker requires `ARCHAI_NATS_BENCH_PATH` plus `ARCHAI_NATS_BENCH_SHA256` before it will query the benchmark. `POST /v1/experiments` records evidence-aware experiments and `/v1/experiments/{experiment_id}` retrieves them. If `ARCHAI_API_KEY` is configured, write operations require the `x-api-key` header.

`ARCHAI_MAX_REQUEST_BYTES` and `ARCHAI_RATE_LIMIT_PER_MINUTE` configure local request guards. In production, enforce these limits at the gateway and/or use a distributed rate-limit store.

Set `DATABASE_URL` to use the SQLAlchemy-backed architecture, search, and experiment registries. The API expects the Alembic schema to have been applied; set `ARCHAI_DB_AUTO_CREATE=1` only for local development or tests. Without `DATABASE_URL`, the API uses process-local registries.
