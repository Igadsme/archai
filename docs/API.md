# API

Redis workers publish heartbeats used by `/v1/infrastructure/workers`, including worker ID, hostname, process ID, liveness timestamp, status, and active job ID. Heartbeats older than 30 seconds are treated as stale and omitted. Experiment creation requires a registered dataset version; supplied evidence checksums must match its registered digest.

`GET /health` and `GET /readiness` report service/configuration status. `GET /v1/infrastructure/workers` and `/v1/infrastructure/queue` expose operational state. `POST /v1/architectures/validate` accepts a strict Architecture JSON document and returns its canonical hash plus analytical metrics. `POST /v1/architectures`, `GET /v1/architectures`, `GET /v1/architectures/{architecture_id}`, and `GET /v1/architectures/compare` provide the local registry surface. `GET /v1/models`, `GET /v1/models/{model_id}`, and authenticated `POST /v1/models` expose and register checksum-backed checkpoint metadata; reads also report whether the artifact exists and still matches its registered digest. `POST /v1/architectures/generate` loads a configured generator checkpoint from `ARCHAI_GENERATOR_CHECKPOINT` and returns independently seeded, canonicalized candidates; it returns `503` when no checkpoint is configured. `POST /v1/searches` creates a budgeted search job and accepts optional benchmark indices; `GET /v1/searches` lists bounded search history; `GET /v1/searches/{search_id}` reports the authoritative job-store status and `POST /v1/searches/{search_id}/cancel` transitions queued/running jobs to cancelled. `POST /v1/training` creates validated candidate, generator, or predictor jobs; `GET /v1/jobs`, `GET /v1/jobs/{job_id}`, and `POST /v1/jobs/{job_id}/cancel` expose generic job lifecycle state. Candidate jobs require synthetic data, generator jobs require explicit corpus/checkpoint paths, and predictor jobs require an archive checksum plus indices. Starting a search returns `503` without Redis, and the durable worker requires `ARCHAI_NATS_BENCH_PATH` plus `ARCHAI_NATS_BENCH_SHA256` before it will query the benchmark. `POST /v1/experiments` accepts predicted evidence directly; benchmark and measured evidence additionally require a dataset checksum, while measured training also requires a model-checkpoint hash and records hardware/code revision. `GET /v1/experiments` lists bounded history, `GET /v1/experiments/{experiment_id}` retrieves a record, and `PATCH /v1/experiments/{experiment_id}` applies validated lifecycle transitions and persists updated metrics. If `ARCHAI_API_KEY` or `ARCHAI_API_KEY_SHA256` is configured, write operations require `x-api-key` or `Authorization: Bearer ...`; request-size limits inspect the actual body when `Content-Length` is absent.

`ARCHAI_MAX_REQUEST_BYTES` and `ARCHAI_RATE_LIMIT_PER_MINUTE` configure local request guards. In production, enforce these limits at the gateway and/or use a distributed rate-limit store.

Training path fields are constrained by `ARCHAI_ALLOWED_PATHS`, a colon-separated list of absolute roots. Local mode defaults to `/tmp` plus Python's temporary directory; Compose sets `/var/lib/archai` so queued workers cannot read or write arbitrary host paths.

Readiness checks database connectivity when `DATABASE_URL` is set. Set `ARCHAI_REQUIRE_REDIS=1` to make Redis connectivity a readiness requirement as well.

Browser clients are allowed only the origins in `ARCHAI_CORS_ORIGINS` (comma-separated); local defaults are `http://localhost:3000` and `http://127.0.0.1:3000`.

Set `DATABASE_URL` to use the SQLAlchemy-backed architecture, search, experiment, model, and dataset registries. The API expects the Alembic schema to have been applied; set `ARCHAI_DB_AUTO_CREATE=1` only for local development or tests. Without `DATABASE_URL`, the API uses process-local registries and the JSON model manifest.
