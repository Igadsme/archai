# API

`GET /health` and `GET /readiness` report service/configuration status. `GET /v1/infrastructure/workers` and `/v1/infrastructure/queue` expose operational state. `POST /v1/architectures/validate` accepts a strict Architecture JSON document and returns its canonical hash plus analytical metrics. `POST /v1/architectures`, `GET /v1/architectures`, `GET /v1/architectures/{architecture_id}`, and `GET /v1/architectures/compare` provide the local registry surface. `GET /v1/models` and `GET /v1/models/{model_id}` expose registered checkpoint metadata. `POST /v1/searches` creates a budgeted search session; status and cancellation are available under `/v1/searches/{search_id}`. `POST /v1/experiments` records evidence-aware experiments and `/v1/experiments/{experiment_id}` retrieves them. If `ARCHAI_API_KEY` is configured, write operations require the `x-api-key` header. Generator and expensive job endpoints remain disabled until authenticated deployment configuration and a real checkpoint are present.

`ARCHAI_MAX_REQUEST_BYTES` and `ARCHAI_RATE_LIMIT_PER_MINUTE` configure local request guards. In production, enforce these limits at the gateway and/or use a distributed rate-limit store.
